# IPTV Pro 添加直播源与导入播放列表

> 播放列表是 IPTV Pro 的全部内容来源。本篇讲清网址和本地文件两条导入路径、m3u 与 xspf 的区别、以及把列表拷进电视盒子时最容易踩的那个坑。

IPTV Pro 是安卓上的网络电视播放器，它自己不含频道，所有频道都来自你导入的那份播放列表。导入这件事本身只有两条路：给它一个网址，或者给它一个文件。但这两条路各自有几个容易卡住的地方，本篇逐个说明。

## 一、先分清你要导入的是哪一种东西

拿到手的东西通常长这三种样子，对应的操作不一样：

| 你手上的东西 | 形态 | 该怎么导入 |
| --- | --- | --- |
| 一串以 `.m3u` 或 `.m3u8` 结尾的网址 | 在线播放列表 | 按「网址」方式导入 |
| 一个几 KB 到几 MB 的 `.m3u` / `.xspf` 文件 | 本地播放列表文件 | 先传到设备上，再按「文件」方式导入 |
| 一长串 `http://域名/get.php?username=...&type=m3u_plus` | 带账号参数的播放列表网址 | 按「网址」方式导入，整串复制，别自己拆 |

有一类容易搞混：提供方给你的地址里带 `<username>`、`<password>` 这类参数，看着像登录信息，其实整串就是播放列表网址本身。这类地址往往**绑定了你的账号**，不要在公开场合贴出来，也别随手转发（见本篇第五节）。

## 二、按网址导入

这是最省事的一条路：列表更新了不用重新导，重新打开或刷新一下就取到新的。

1. 打开 IPTV Pro，进播放列表管理页，选「添加播放列表」；
2. 选择「网址」这一项（不同版本的按钮文案略有差异，认「地址 / URL」那个即可）；
3. 给播放列表起个能认出来的名字，比如「运营商 IPTV」「客厅源」—— 你以后可能会同时挂好几份，名字乱起后面会疼；
4. 把整串地址粘进去，点确定；
5. 等它拉取并解析频道。

**粘贴地址的三个坑**：

- **别漏掉开头的 `http://` 或 `https://`**。少了协议头，多数版本会直接报地址无效；
- **别带多余的空格和换行**。从聊天记录里复制最容易在首尾粘上空格，肉眼看不出来但会解析失败；
- **别手动改大小写**。`username`、`password` 这类参数多数是区分大小写的，改一个字母就变成另一个账号。

## 三、按本地文件导入

适合这两种情况：提供方给的就是一个文件；或者你想把同一份列表装到多台设备上，不想每台都去填地址。

1. 把 `.m3u` 或 `.xspf` 文件传到设备上（数据线、U 盘、局域网传输都行，文件管理器能看到的目录就可以）；
2. 在 IPTV Pro 里选「添加播放列表」→「文件」，进文件选择器找到它；
3. 选中后应用会即时解析，成功的话频道列表立刻出来。

**关于文件放哪个目录**：安卓 11 之后系统对存储访问管得更紧，放在「下载」或「文档」这类标准目录下最稳，文件选择器默认也能直接看到。放在某些应用专属目录里，文件选择器可能翻不到。

## 四、拷到电视盒子 / 电视上的那个坑

如果你是用数据线把播放列表从电脑拷到设备的 SD 卡或外置存储，**要专门建一个目录、并在里面放一个空文件命名为 `.nomedia`，把播放列表放进这个目录**。这不是洁癖 —— 安卓的媒体扫描会把外置存储上的 `.m3u` 当媒体索引文件处理，电脑一断开连接，扫描过程可能会把你的播放列表删掉。

`.nomedia` 是个零字节文件，作用是告诉系统「这个目录别扫」。电脑上新建一个文本文档、把文件名改成 `.nomedia`（连扩展名一起去掉）即可。

如果设备是通过 U 盘或蓝牙拿到的文件，走的是文件管理器而不是媒体扫描，不受这条影响。

## 五、多个播放列表怎么管理

应用支持同时挂多份播放列表，并按历史记录保留你导入过的列表。实用的分工方式：

| 场景 | 建议 |
| --- | --- |
| 运营商给的源 + 自己订阅的源 | 各建一份，名字区分开，哪个看着顺用哪个 |
| 一份源里的频道太多 | 先看它是否自带分类（见下节），自带分类就不用拆 |
| 临时试用的源 | 单独建一份，试用完直接删，别和长期在用的混在一起 |

删除播放列表等于把那份列表从应用里移走，不会影响提供方那边的账号状态。

## 六、源那边改了，你这边怎么跟上

提供方加台、撤台、换流地址，都是你改不了的事。你的列表能不能跟着变，取决于当初是用哪种方式导入的：

| 导入方式 | 源更新之后 | 你该做什么 |
| --- | --- | --- |
| 网址 | 应用重新拉取时取到的是最新一份 | 重新加载那份播放列表即可；同时留意提供方给你的地址本身有没有换 |
| 本地文件 | 导入的是**当时那一份快照**，源改了它不会变 | 重新取一份新的列表文件，或者换成用网址导入 |

记不清当初用的哪一种：播放列表的详情里通常能看到来源是网址还是文件名。两种方式各有各的用处 —— 网址省事但依赖提供方的服务器，文件稳但不会自己更新。

另一类看着像「源更新了」、其实是账号侧变化的情况：提供方给你的那串地址里带账号参数，换套餐、换线路时地址会换一条。旧地址未必立刻失效，但会慢慢变成大面积打不开。遇到这种情况先去问提供方要新地址，不要急着删列表重配。

## 七、频道分类从哪来

频道按「新闻 / 体育 / 电影」这类分组显示，靠的是**播放列表文件里自带的分组信息**，不是应用自己猜的。你的 m3u 里每个频道带有分组属性（这是 m3u 扩展示例里的常规写法），导入后就能按组浏览；列表本身没写分组，那界面上就只有一长串频道。

所以「没有分类」不是设置项没打开，而是列表里没写。要分组就得从提供方那边解决，或者自己整理播放列表文件。列表格式里的分组写法，官方描述里指向的是播放列表格式说明那一份文档，你可以让提供方按同一套格式给你。

## 八、导入完确认什么

1. **频道数量对不对**：和提供方给的数字大致对得上，差几个正常（下架的频道），差一个数量级说明列表拉了一半就断了；
2. **随便点一个频道能放**：能出画面出声音，说明列表里的地址是活的；
3. **节目单一栏有没有内容**：有内容说明列表里带了节目单地址，空的就看 [节目单与EPG怎么设置.md](节目单与EPG怎么设置.md)；
4. **切几个频道试试**：连着切三四个都不黑屏，才算这份列表真能用；
5. **看一眼地址类型**：列表里全是 `http://` 开头的，直接看就行；出现 `udp://` 这类，先过一遍 [局域网组播与UDP代理怎么用.md](局域网组播与UDP代理怎么用.md)。

列表拉不出来、频道点开一直转圈，按 [播放卡顿与连不上怎么排查.md](播放卡顿与连不上怎么排查.md) 第一节的三步交叉验证先定位责任方 —— 这一步能帮你省掉大量在应用里乱改设置的时间。
