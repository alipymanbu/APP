# IPTV Pro 局域网组播与UDP代理怎么用

> 运营商宽带里带的电视源常是组播，直接播往往一卡一顿甚至完全不出画面。本篇讲怎么判断你手上的源是不是组播、UDP 代理起在哪、以及播放列表里的地址要怎么改。

这是 IPTV Pro 里最不「手机 App」的一块功能：它支持通过局域网里的 UDP 代理来播放组播流。官方描述里给这条加了限定 —— **代理必须装在你自己的局域网内**，用不了别人家的。本篇按「先判断、再搭建、最后改地址」的顺序说。

## 一、先判断你手上的源是不是组播

打开你的 `.m3u` 文件，看频道地址那一行（`#EXTINF` 后面的那一串）：

| 地址开头 | 类型 | 要不要走代理 |
| --- | --- | --- |
| `http://` 或 `https://` | 单播，普通网络流 | 不需要，直接播即可 |
| `udp://@239.x.x.x:端口` | 组播（UDP） | 需要 UDP 代理 |
| `rtp://@239.x.x.x:端口` | 组播（RTP） | 需要 UDP 代理 |
| `udp://@224.x.x.x` 到 `239.255.255.255` 之间 | 组播地址段 | 需要 UDP 代理 |

组播地址是 `224.0.0.0` 到 `239.255.255.255` 这一段，其中 `239` 开头的最常见。地址前面带 `@` 符号也是组播的典型写法。

**为什么这类源直接播不行**：组播是给局域网内部「一对多」分发设计的，普通家庭 Wi-Fi 环境里，手机、平板这类设备对组播的支持参差不齐，走无线时尤其容易丢包。加上一层代理把组播转成普通的 HTTP 单播流，播放器就能像放网络视频一样处理它 —— 这就是下面要搭的那层东西的作用。

如果你手上的源全是 `http://` 开头的，**这篇可以整篇跳过**，你的卡顿问题属于另一类，见 [播放卡顿与连不上怎么排查.md](播放卡顿与连不上怎么排查.md)。

## 二、代理要起在哪

三种位置，按省事程度排序：

| 位置 | 优点 | 代价 |
| --- | --- | --- |
| **路由器上** | 一次配置，全家设备都能用；不用一直开着某台电脑 | 需要路由器支持（固件里自带或能刷） |
| 局域网里常开的电脑 | 配置最简单，官方直接给了 Windows 版工具 | 这台电脑必须开着，且不能休眠 |
| 树莓派 / NAS 等常开小主机 | 不占主力电脑，长期稳定 | 需要一点命令行操作 |

判断自家路由器能不能直接用：进路由器管理页面找「组播」「IPTV」「udpxy」相关字样。**部分无线路由器的原厂固件里就内置了 udpxy**，官方描述里明确提到这一点 —— 先在管理页面里翻一遍，别急着买设备。没有的话，刷 DD-WRT 或 OpenWrt 固件可以补上这个能力（对应固件项目页面见下方链接）。

## 三、Windows 上起一个代理

官方描述里点了两个 Windows 侧的做法：

1. **单独的 UDP-to-HTTP 代理程序**：从 [borpas.info/download/UdpProxy.exe](http://borpas.info/download/UdpProxy.exe) 下载，直接运行，它会监听在本机的一个端口上，把收到的组播地址转成 HTTP 流；
2. **安装 IP-TV Player 时勾选对应选项**：IP-TV Player 的安装向导里有一步是「顺带装 UDP 代理」，勾上即可（该播放器的页面在 [borpas.info/iptvplayer](http://borpas.info/iptvplayer)）。

两种方式得到的是同一类代理，起起来之后都要注意一件事：**让这台电脑的防火墙放行代理监听的那个端口**。否则手机连得通但一直拉不到流，现象和代理没起来一样。同时关掉这台电脑的睡眠，它一睡，你的电视就停。

## 四、在 Linux 或路由器上跑 udpxy

udpxy 是这一类代理里用得最广的一个，很多固件内置的就是它。官方描述里给的资料入口：

- Linux 上安装 udpxy：[udpxy.com/index-en.html](http://udpxy.com/index-en.html)，源码托管在 [sourceforge.net/projects/udpxy](http://sourceforge.net/projects/udpxy/)
- 刷在路由器上：DD-WRT 的固件项目在 [www.dd-wrt.com](http://www.dd-wrt.com)，OpenWrt 在 [openwrt.org](https://openwrt.org)

udpxy 的核心参数只有一个必须搞清楚：**它监听哪个端口**。默认常见的是 `4022`，你自己改过就以改后的为准 —— 下一步拼地址时要用到它。

## 五、把播放列表里的组播地址换成代理地址

代理起来之后，播放列表里那些 `udp://@` 地址都要改成经过代理的 HTTP 地址。转换规则很固定：

```
原始：udp://@239.255.1.1:1234
改后：http://<代理所在设备的局域网IP>:<代理端口>/udp/239.255.1.1:1234
```

举两个例子，假设代理跑在 `192.168.1.2` 上、监听 `4022` 端口：

```
原始：udp://@239.255.1.1:1234
改后：http://192.168.1.2:4022/udp/239.255.1.1:1234

原始：rtp://@239.0.0.1:5000
改后：http://192.168.1.2:4022/rtp/239.0.0.1:5000
```

三处要对：

- **局域网 IP** 是代理设备在你家内网里的地址（`192.168.x.x` 这类），不是公网地址，也不要用设备名；
- **端口** 是第三、四节里代理监听的那个；
- **`udp/` 还是 `rtp/`** 取决于原始地址的开头，原来是什么就写什么，然后接原始的组播地址和端口。

改法有两种：把 `.m3u` 用文本编辑器全局替换后再导入（推荐，一次搞定）；或者在应用里逐个频道改地址（频道多的时候不现实）。改之前先备份原文件。

代理设备换 IP 或者你换了路由器，这批地址全部失效 —— 所以尽量在路由器上给代理设备绑定一个固定内网 IP，能省掉以后反复改列表的麻烦。

## 六、常见现象对照

| 现象 | 多半是什么原因 |
| --- | --- |
| 改完地址后所有组播频道都打不开 | 代理没起来、端口写错、或防火墙没放行 |
| 手机连不上、电脑上能播 | 代理跑在电脑上且只监听了本机回环，需要让它监听所有网卡 |
| 能播但花屏、顿 | 组播放到 Wi-Fi 上本身就不稳，优先把播放设备接网线；确认走的是千兆网口 |
| 换台要等好几秒 | 组播切换频道时建流本身有延迟，属正常范围 |
| 过一段时间全部失效 | 代理那台机器休眠了或重启后没自启 |
| 只有部分频道打不开 | 个别组播地址在运营商侧已下架，与代理无关 |

组播这条路本质上是绕不开网络环境的：能接网线就接网线，代理设备要常开，路由器固件要支持。这三条里缺哪条，体验都会明显打折。
