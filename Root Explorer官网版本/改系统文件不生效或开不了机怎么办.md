# Root Explorer 改系统文件不生效或开不了机怎么办

> 改完系统配置没反应、和重启后卡在开机画面，是两种不同的问题。本篇给出「为什么不生效」的五项排查，以及出事后按代价排序的处理路径。

## 一、改了没生效：按这五项挨个查

以最常见的 `build.prop`（`/system` 下的系统属性文本文件，逐行 `键=值`）为例。它的改动要生效，下面五项缺一不可：

| 顺序 | 检查项 | 怎么确认 |
| --- | --- | --- |
| 1 | 内容真的写进文件了吗 | 用文本编辑器重新打开文件，翻到那一行看改动还在不在 |
| 2 | 分区当时是可写状态吗 | 保存前后都看路径栏右侧的 `r/w`；只读状态下的「保存成功」常常只是假象 |
| 3 | 文件权限还是 `rw-r--r--`（644）吗 | 长按 → 权限确认。用编辑器覆盖保存后另存，权限有时会变 |
| 4 | 所有者还是 `root:root` 吗 | 长按 → 属性确认。所有者变了，系统可能直接忽略这个文件 |
| 5 | 是否**完整关机再开机** | 属性类配置在启动时读取；普通重启有时不会重新读，关机再开机才可靠 |

## 二、五项都对，还是不生效

还有两个原因与你的操作无关：

- **改动被上层方案覆盖。** 通过 Magisk 一类工具 root 的机型，系统分区实际是叠加层，你在文件管理器里改的 `/system` 内容不会成为最终生效的那一份。表现很典型：**在文件管理器里改得很成功、重启后毫无变化**。这类环境下系统属性要在模块配置里改，而不是直接改系统文件。
- **改动位置写错了。** `键=值` 的格式里多一个空格、键名拼错一个字母，系统会当作无效行整行跳过——不报错，也不生效。

判断顺序建议是：先按本节第一条（换成模块配置那个位置去改）试一次，再逐行核对改动本身有没有写错。

## 三、卡在开机画面：按代价从低到高处理

**第一步，先进恢复模式（Recovery）。** 关机后按机型对应的组合键进入（常见是电源键 + 音量上或音量下，具体组合查你的机型）。能进恢复模式，就还有软处理的空间；进不去，直接看第三步。

**第二步，把备份换回去。**

- 有**系统分区的整盘备份**（自定义 Recovery 里的整盘备份）：直接还原，这是最干净的一条路。
- 只备份了**被改的那个文件**：在恢复模式的文件管理器里把它复制回原位，改好权限与所有者，再重启。
- 什么都没备份：跳到第三步。

**第三步，刷回官方固件。** 下载对应机型的官方固件包重刷；解锁过 Bootloader 的机型，多数厂商要求走官方渠道处理。

**一条经验**：出问题后**不要反复重启试探**。每一次重启都在消耗时间和电量，问题通常不会自己变好——先想清楚刚才是哪一步动的手，再按上面的顺序处理。

## 四、以后怎么避免

- **改之前把原件复制一份到用户存储**，文件名带上日期，恢复时不用猜是哪一版。
- **一次只改一个文件、一个值**，改完立刻验证。
- **别只用「重启」去验证。** 该完整关机再开机的一次都不能省，否则很容易误判成「没生效」而反复改动同一个文件。

删除系统文件和改系统配置属于同一类操作，出事之后的恢复思路也是共用的——删错了东西的情况见 [删错了系统应用怎么恢复.md](删错了系统应用怎么恢复.md)。
