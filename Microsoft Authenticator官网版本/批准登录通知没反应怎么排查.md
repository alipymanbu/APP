# Microsoft Authenticator 批准登录通知没反应怎么排查

> 登录时电脑上等着点批准、手机上却什么提示都没有 —— 按顺序查这十步，并分清哪些账号本来就没有推送。

登录页写着「打开 Microsoft Authenticator 并批准请求」，手机上却始终不弹，是这类应用最常见的一类卡壳。它通常不是账号问题，而是推送没到手机上。本篇按从快到慢的顺序给一套排查流程，最后附几个专属报错的读法。

## 一、先把两件事分开

很多人把「验证码」和「登录批准」当成一回事，其实它们的联网要求完全不同，这也决定了排查方向：

| 用途 | 要不要联网 | 收不到时该查什么 |
| --- | --- | --- |
| 6 位动态验证码 | 不要 | 时间同步，见 [验证码不对怎么办.md](验证码不对怎么办.md) |
| 登录批准通知 | 要 | 推送通道、通知权限、账号绑的是哪台设备 |

所以「码能显示、通知收不到」是正常的两种现象，不要去动时间设置。

## 二、按顺序自查这十步

1. **确认账号在列表里**：打开 Authenticator，看要登录的这个账号在不在。账号不在了说明绑定关系已经失效，得重新加，见 [添加账户与绑定验证码.md](添加账户与绑定验证码.md)。
2. **确认应用没被锁着**：开了应用锁时，工作或学校账号常常要先解锁应用才能批准。先解锁，再看有没有待处理的请求。
3. **在应用里下拉刷新**：**有些登录根本不会产生推送**，请求只出现在应用内部，必须进去手动批准。这一条能解决很大一部分「没收到通知」。
4. **登录页换一条路**：在登录界面选「其他登录方式」，看有没有「在我的 Microsoft Authenticator 应用中批准请求」这一项，有就直接从那里发起。
5. **查通知开关**：系统设置里给 Authenticator 通知权限，应用内「设置 → 通知设置 → 显示通知」也要是开的。两项都在才对。
6. **查免打扰、静音、专注模式**：手机处于免打扰或静音时，通知会被压掉。确认能收到别的应用的通知 —— 如果所有应用都收不到，问题是网络或系统级的。
7. **关掉电池优化（安卓）**：在系统设置里把 Authenticator 的电池优化关掉，后台同步才不会被限制。
8. **查网络**：数据与 Wi-Fi 互切一次，关掉飞行模式；开着 VPN 的话断开再试。
9. **查日期与时间**：系统时间设成自动。时间偏差不光影响验证码，也会影响推送的时效判定。
10. **查版本**：微软明确表示**不支持超过一年的旧版本**，在应用商店更新到最新。

## 三、通知是不是跑到旧手机上了

这是换机之后最典型的情况：**推送会发到最近一次使用过 Authenticator 的那台设备**。旧手机还在、还装着这个应用，通知就继续往它那里去，新手机上自然什么都没有。

要彻底改掉，光在新手机上加账号不够，必须把旧的注册关系解除：

- **个人 Microsoft 账号**：到 [account.microsoft.com/security](https://account.microsoft.com/security) 的两步验证区域，关闭旧设备的验证；
- **工作或学校账号**：到 [myapps.microsoft.com](https://myapps.microsoft.com) 或所在组织的公司门户，在同样的区域关掉旧设备。

**只在旧手机上卸载应用是没用的** —— 注册关系还在账号里。做不到这一步时，先去旧手机上把当次请求批准掉，把眼前的登录解决掉，再回来处理注册。

## 四、哪些账号本来就没有推送

这一条能省掉很多无效排查：

| 账号类型 | 有没有一键批准推送 |
| --- | --- |
| Microsoft 个人账号 | 有 |
| 工作或学校账号 | 有，但由组织 IT 管理员决定是否开放，可能被关掉 |
| 第三方账号（Google、Facebook、Amazon 等） | **没有**，只能用 6 位验证码 |
| 中国区的账号 | **没有**，详见 [常见问题与排查.md](常见问题与排查.md) |

第三方账号收不到批准提示不是故障，回登录页找「使用验证码」这一类选项即可。

## 五、两个通知专属报错

- **「通知始终过期」**：官方给的定位是设备时钟必须准确报告本地时间。把系统时钟改成自动获取，改完**重启一次设备**，再看新时间对不对。手动设过时间的机器尤其容易中这一条。
- **「通知显示的地址或位置不正确」**：这条一般和组织配置的登录地点策略有关，属于管理员侧问题，自己改不动，带上截图找 IT 支持。

## 六、走完全部还是不行

按顺序做最后三件事：

1. **在应用里发反馈**：打开 Authenticator 的顶层菜单，找「发送反馈」，把日志带出去。个人账号找微软支持、工作或学校账号找 IT 支持时，这份日志能省一轮往返。
2. **工作或学校账号：请管理员重置注册**。让对方在 Entra 管理端对你的账号选择「需要重新注册多重身份验证」，然后你重新扫一次码。
3. **个人账号：走登录助手**。其他验证方式（备用邮箱、手机号）还能用的话，先登录把安全信息补齐；都用不了再走微软账户恢复流程，这条路的处理时间按官方流程走。

**顺手提醒一句**：如果手机上弹出的批准请求不是你发起的，一律选拒绝，并顺手改一次密码。这类「登录轰炸」本身就是攻击行为。
