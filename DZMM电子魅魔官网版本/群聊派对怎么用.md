# 群聊派对怎么用

> 想在一个对话里同时和好几个角色互动时，用群聊；本篇讲怎么开、怎么不让它变成一锅粥，以及它的代价。

## 一、群聊和一对一差在哪

一对一里只有一个角色说话。群聊把**多个角色放进同一条对话**，他们能互相回应、互相拆台，适合阵营对抗、关系网、多方谈判这类一个人撑不起来的玩法。

想弄清单个角色怎么聊，见 [怎么挑角色和开始聊天.md](怎么挑角色和开始聊天.md)。

## 二、怎么开一个群聊

入口名称随版本不同，路径大致是「创作 / 角色管理 → 新建群聊或多角色对话」：

1. 新建一个群聊，给它一个场景名（比如「三人对峙」），场景名本身就是给模型的背景交代。
2. 拉角色进来。**建议 2~4 个**，再多注意力会被摊薄。
3. 给每个角色补一句立场：谁跟谁一伙、谁对谁有意见。关系写清楚了，冲突才有来由，不然会变成客气的轮流发言。
4. 开始后，可以指定谁说话，也可以让模型自己分派。
5. 角色素材不够用，先按 [角色卡怎么创建与导入.md](角色卡怎么创建与导入.md) 把需要的人建出来或导入进来。

## 三、不让它变成一锅粥

| 做法 | 效果 |
| --- | --- |
| 指定发言 | 一次只让一两个角色回应，避免每人一句的流水账 |
| 写明关系 | 态度与立场固定下来，对话才有张力 |
| 阶段总结 | 剧情绕远时让它先总结当前局势再往下走 |
| 控制人数 | 超过四个角色，模型会顾此失彼、串人设 |

## 四、要接受的代价

- **更慢、更耗额度**：一轮里要让多个角色产出内容，等待时间和消耗都会上去，见 [电量和会员怎么算.md](电量和会员怎么算.md)。
- **更容易串人设**：角色越多越容易张冠李戴，出现这种情况就精简人数或重开一条。
- **入口与命名不统一**：不同版本的叫法和位置不同，本文的路径以你当前版本的界面为准。
