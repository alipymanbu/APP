手机上写 Java，编译器本身很少出问题，麻烦大多来自输入法：它按"给聊天用的"逻辑优化，而写代码恰恰需要它别自作聪明。

## 一、先关掉这两项（最要紧）

| 功能 | 通常叫什么 | 写代码时的后果 |
| --- | --- | --- |
| 自动纠错 / 自动更正 | 智能纠错、自动更正、拼写纠正 | 把 `String` 改成 `string`、把 `count` 改成 `Count`，编译直接报 `cannot find symbol`，而你看着代码怎么都对 |
| 自动大写首字母 | 句首大写、自动大写 | 变量名首字母被悄悄改成大写，尤其是换行之后第一个单词 |

这两项在输入法的设置里都能关（常见的路径是"设置 → 文本输入 / 输入设置 → 自动更正"）。关掉之后输入会变成"打错就是打错"，比被悄悄改写好得多。

**中文输入法的"智能标点"也要留意**：它会把 `"` 变成 `“`、`(` 变成 `（`、`;` 变成 `；`，而 Java 只认半角符号。写代码时把输入法切到**英文状态**，比事后逐行找全角符号省事得多——这类报错长什么样见 [编译报错与代码联想怎么处理.md](编译报错与代码联想怎么处理.md)。

## 二、让符号输入快起来

`{}`、`(`、`)`、`;`、`"` 是写 Java 时敲得最多的五个符号，改一下输入法的用法能省很多次切面板：

- **长按字母键直接出符号**。多数输入法支持在按键上长按输入对应符号（部分输入法的开关名是"通过长按来输入符号"），开启后 `;` 可以长按某个键直接得到，不必每次切到符号面板；
- **记住符号面板的第二页**。`{}` 这类花括号多数输入法不在第一页，翻一次之后位置就固定了，直接点比找快；
- **别用九宫格**。九宫格拼音在中文输入时手感好，但英文与符号输入效率低，写代码时要么切全键盘，要么直接用英文键盘布局。

## 三、想更接近电脑键盘，可以换一类键盘

安卓上有一类"五排布局"的第三方键盘（例如基于 AOSP 键盘的 Hacker's Keyboard，包名 `org.pocketworkstation.pckeyboard`），特点是把电脑键盘的排布搬过来：数字与符号常驻一排，并带 `Ctrl`、`Tab`、`Esc`、方向键，支持 `Ctrl+C`、`Ctrl+V` 这类组合键。

- **适合的场景**：平板、折叠屏这类屏幕够大的设备，或者你经常要按 Tab 缩进、用方向键移动光标；
- **不适合的场景**：普通手机竖屏。五排键在 6 英寸左右的屏幕上每颗键都很小，误触率会明显上升；
- **如果要装**：第三方键盘能看到你输入的一切内容，尽量选开源、权限说明清楚的那一类，别用来路不明的。

这是**可选项**——只关掉第一节那两个开关，体验就已经好一大半了。

## 四、屏幕与行宽

- **横屏写长语句**：一行 `if (a > 0 && b < 10) { ... }` 在竖屏会被折成两三行，横屏通常能一行放下，括号配对更容易看清；
- **字号与字体**配合着调，原则是"宁可小一号也别频繁折行"，具体见 [主题字体与编辑器设置.md](主题字体与编辑器设置.md)；
- **关掉自动旋转的干扰**：如果你习惯竖屏，把系统旋转锁打开，避免躺着用手机时屏幕突然横过来。

## 五、改完做一次验证

用下面这段同时含字符串、花括号、分号和自增的小程序，把改过的输入法走一遍：

```java
public class Typing {
    public static void main(String[] args) {
        int count = 0;
        count++;
        System.out.println("count = " + count);
    }
}
```

重点看三处：`String`/`System` 的大小写有没有被自动纠正改掉、`"` 有没有被换成全角、`;` 是不是半角。这三点都能保持原样，输入法就算配好了，可以回 [第一个程序怎么跑起来.md](第一个程序怎么跑起来.md) 继续往下写。
