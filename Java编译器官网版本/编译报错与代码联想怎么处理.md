手机上写 Java 报错，多数不是"软件有问题"，而是三类原因：全角标点、文件名与类名不一致、名字拼错。这篇把报错信息拆开读，并给出常见错误的对照处理。

## 一、先学会读一段报错

一段编译报错通常包含三样东西，按下面的顺序看：

1. **行号**：报错指的那一行往往不是真正出错的地方——缺一个右括号，报错可能落在后面十几行的位置；
2. **错误类型**：`';' expected` 是缺符号，`cannot find symbol` 是名字找不到，两者处理方式完全不同；
3. **第一条错误优先**：编译是边扫边报的，第一条之后的很多条常常是它的连锁反应，先只修第一条再重新运行。

更新说明里提到报错信息支持复制。**把报错原文整段复制出来**再去找答案，比自己概括成"运行失败了"有用得多——错误类型、类名、方法名都在里面，搜的时候带上它们命中率高很多。

部分版本会给出中文报错提示。中英对照大致是这样：

| 报错里的关键词 | 中文意思 | 常见原因 |
| --- | --- | --- |
| `';' expected` | 这里应该有一个分号 | 漏写分号，或写成了全角 `；` |
| `cannot find symbol` | 找不到这个名字 | 变量/类名拼错、大小写不一致、忘了 `import` |
| `illegal character: '\uff1b'` | 出现了非法字符 | 全角标点（`\uff1b` 就是全角分号） |
| `incompatible types` | 类型不兼容 | 把字符串赋给数字、把数字当字符串用 |
| `missing return statement` | 缺少 return | 声明了返回值的方法里没有 `return` |
| `should be declared in a file named ...` | 类应该声明在同名文件里 | 文件名与 `public class` 的类名不一致 |

## 二、手机上最高发的四类错误

**第一类：全角标点。** 中文输入法下的 `；`、`（`、`）`、`“`、`”` 与英文半角长得几乎一样，但 Java 只认半角。报错常写成 `illegal character` 或指向某一行的奇怪位置。处理办法：把输入法切回英文，删掉这一行的标点重新敲。写代码时养成先切输入法的习惯，比事后逐行找要省事。

**第二类：文件名与类名不一致。** 报错原话是 `class X is public, should be declared in a file named X.java`。要么把文件重命名成与类名一致，要么把类名改成与文件一致——两边改哪边都行，改了哪边另一边就跟着改。

**第三类：名字拼错或大小写不一致。** `System.out.println` 写成 `system.out.println`、变量声明是 `count` 用的时候敲成 `Count`，都会报 `cannot find symbol`。核对时注意：Java 大小写敏感，`String` 和 `string` 是两个东西。

**第四类：用了没引入的库。** 代码里 `import` 了一个项目里没有的包，或加了 `jar` 却没放进项目，报错同样是 `cannot find symbol` 或"找不到包"。这时要回头确认依赖有没有真的加进项目，做法见 [项目与代码文件怎么管理.md](项目与代码文件怎么管理.md)。

## 三、代码联想不出现怎么办

代码联想属于编辑器功能，不出现时不必怀疑安装。按这个顺序排查：

1. **继续敲一两个字符**：联想通常要在输入 `.` 或前几个字母之后才弹出来，刚敲一个字母不弹是正常的；
2. **看是不是当前文件没被识别**：从文件管理器直接打开的 `.java` 文件，若缺少合法的类声明，编辑器可能按纯文本处理，联想会弱很多；
3. **确认输入法没在吃按键**：中文输入法的候选栏会挡住联想弹窗，写代码时保持英文输入状态；
4. **换一次版本试试**：开发方的更新记录里出现过"修复代码联想功能"这类条目，说明联想在旧版本里确实偶有问题。若你手上这一版联想长期不灵，可以换网盘里更新的一份包重装（先卸载再装，代码文件提前拷出来，见 [项目与代码文件怎么管理.md](项目与代码文件怎么管理.md)）。

联想的强弱与字体、字号、注释高亮这些设置放在一起，都在编辑器设置里，见 [主题字体与编辑器设置.md](主题字体与编辑器设置.md)。

## 四、分清「报错」和「没反应」

这两件事的处理路径不同，别混在一起查：

- **结果区给出了错误信息** → 是编译没过，按上面第一、二节的对照表改代码；
- **结果区一直停着，既不输出也不报错** → 先看程序里有没有 `Scanner(System.in)` 这类要从键盘读数据的写法：手机上的编译运行环境通常不提供控制台输入通道，程序很可能卡在等待输入上。判断方法与三种绕法见 [键盘输入的程序为什么卡住.md](键盘输入的程序为什么卡住.md)；
- **点了运行完全没反应、也没有在等输入** → 这多半不是编译报错，而是软件或环境层面的问题，到 [常见问题与排查.md](常见问题与排查.md) 里对"点运行没反应"那一条。

改完代码记得重新点运行——编译是对当前这一份代码做的，改了不重跑不会自己更新结果。
