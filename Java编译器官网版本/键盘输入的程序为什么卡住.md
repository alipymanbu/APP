# Java编译器 键盘输入的程序为什么卡住

> 带 `Scanner` 的程序一点运行就停住、既不输出也不报错——这通常不是代码写错，而是运行环境没有"键盘输入"这条通道。这篇讲怎么确认、怎么绕开。

学到输入这一章，代码就成了这样：

```java
import java.util.Scanner;

public class Sum {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        int a = sc.nextInt();
        System.out.println(a * 2);
    }
}
```

这段代码在电脑上运行会停下来等你敲一个数字，但在手机上点运行，很可能就是**一直停着**：没有输出，也不报错，等多久都不会动。

## 一、先确认是不是"卡在等输入"

判断标准有三条，同时符合基本就是了：

1. 程序里用了 `Scanner(System.in)`、`System.in.read()` 或 `BufferedReader` 包着 `System.in`；
2. 点运行后结果区**什么都没出现**——既没有输出，也没有编译错误；
3. 把 `sc.nextInt()` 换成一句 `int a = 3;` 之后同样的程序立刻就能跑出结果。

如果是这样，问题不在你的代码，也不在语法上。

## 二、为什么会这样

Java 里的 `Scanner(System.in)` 要从"标准输入"读数据，也就是电脑上的键盘与控制台。手机上的这类编辑器是**在一个没有控制台的环境里运行代码**的：很多在线编译器与嵌入式编译环境都不提供 `System.in`，程序读不到东西就会一直等下去，表现就是卡住不动（既不出结果也不报错）。

**本套文档无法确认当前这一版在这一点上的具体行为**，也无法预判后续版本会不会补上键盘输入界面——以你手机上那一版的实际表现为准。但无论哪一版，"交互式输入在手机上不好用"这件事都有成熟的绕法，见下节。

## 三、三种绕法

**绕法一：把输入直接写进代码（最省事）。** 学语法、练算法时，输入值其实不重要，把 `nextInt()` 换成常量即可：

```java
public class Sum {
    public static void main(String[] args) {
        int a = 7;              // 原来这里是从键盘读
        System.out.println(a * 2);
    }
}
```

要点是**每次只改这一处**，程序逻辑不动，验证完再换一个值跑一次，效果和手动输入是一样的。

**绕法二：把测试数据放进数组或循环。** 要验多组数据时，不要反复改常量，把用例排成数组：

```java
public class Sum {
    public static void main(String[] args) {
        int[] cases = {7, -3, 0, 120};
        for (int a : cases) {
            System.out.println(a + " -> " + (a * 2));
        }
    }
}
```

**绕法三：把"读输入"和"算逻辑"分开。** 这是最值得养成的习惯：

- 在手机上只写并测试**计算方法**（传入参数、返回结果，不碰 `System.in`）；
- 涉及真实交互的部分，等回到电脑上再补 `Scanner`，或者干脆用带终端的环境来跑。

这样写出来的代码，在手机和电脑上都能测。

## 四、确实要测键盘输入怎么办

- **换一类工具**：带完整终端的环境可以真的接受键盘输入（例如终端模拟器类应用，装完还要自己用命令装 JDK；这类工具与本文这份 Java编译器 不是同一个东西，区别见 [同名应用与官方渠道怎么认.md](同名应用与官方渠道怎么认.md)）；
- **回到电脑**：真正要调试交互流程时，电脑上的 IDE 或命令行是最省心的选择，手机上不必勉强。

## 五、别和"报错"混起来

这两种现象处理路径完全不同：

| 现象 | 属于哪一类 | 去哪一节 |
| --- | --- | --- |
| 结果区给出了错误信息（行号 + 错误类型） | 代码问题 | [编译报错与代码联想怎么处理.md](编译报错与代码联想怎么处理.md) |
| 结果区一片空白、程序停住 | 输入通道问题 | 本篇第一、三节 |
| 点运行毫无反应、也没在等待 | 环境问题 | [常见问题与排查.md](常见问题与排查.md) |

把 `Scanner` 换成常量之后程序能跑出结果，就基本可以确认是输入通道的问题，而不是这个软件坏了——按第三节的绕法继续练习即可。
