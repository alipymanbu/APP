# qBittorrent Controller 连接不上与报错排查

> 这个应用的报错文案是固定的几条英文句子，看懂它们等于拿到一半答案：有的指向地址填错，有的指向账号密码，有的只是证书问题。本篇先把每条原文的含义对上，再给一个从近到远的排查顺序，最后说账号密码、Host 校验与自签名证书这几个高频坑。

## 一、先把报错原文对上

下面几句都是应用里会原样弹出来的，遇到时对号入座，能省掉大半排查时间：

| 应用里的原文 | 含义 | 先去查 |
| --- | --- | --- |
| `The host or IP address cannot be reached. Please check your settings!` | 按你填的主机名与端口根本没连上 | 第二节第 1~5 步 |
| `Network connection failed` | 网络这一层就不通（手机没网、不在同一网络） | 第二节第 1、8 步 |
| `Unauthorized access. Check your account settings to avoid bans!` | 服务端拒绝了这次登录（401），多为账号或密码不对 | 第三节、第四节 |
| `Authentication error` | 认证失败（403），可能是凭据不符、来源 IP 被临时封禁，也可能是 Host 校验没过 | 第四节 |
| `HTTPS certificate error!` | 开了 HTTPS，但证书手机不认（自签名证书最常见） | 第五节 |
| `Global value cannot be retrieved. Please check your connection settings!` | 能连上但取不到服务端数据，通常是连接参数或子路径填错 | 第二节第 5、10 步 |
| `No torrents found` | **不是报错**：连上了，只是这个分组下没有任务 | 无需处理 |
| `Storage access required to download and send torrent files!` | 与连接无关：用「添加种子文件」时缺存储权限 | 去系统设置补权限 |

## 二、从近到远的排查顺序

**第 0 步永远先做**：拿手机的浏览器访问 `http://服务端IP:端口`（例：`http://192.168.1.124:8080`）。这一步把问题一分为二 —— 浏览器能出登录页，说明服务端与网络都没问题，问题在应用里的设置；浏览器也打不开，就别在应用里折腾了，往下查。

1. **手机和服务端是不是同一个网络。** 手机连的 Wi-Fi 与电脑插的路由器必须是同一台。手机走的是 4G/5G、或连了另一个路由器，局域网地址一律不通。想在外面连，先看 [在外网连接家里的服务器.md](在外网连接家里的服务器.md)。
2. **服务端的 Web UI 是不是开着。** 工具 → 选项 → Web UI，看「Web 用户界面（远程控制）」有没有勾上。改过之后要点「应用」，有的改动还要重启 qBittorrent 才生效。
3. **端口有没有对上。** 服务端那一栏的端口，必须与应用「高级 → 连接端口」里填的完全一致。默认都是 `8080`，但服务端改过就不是了。
4. **主机名有没有多写东西。** 不要带 `http://`，也不要把端口写进主机名字段，例如 `192.168.1.124:8080` 是错的写法，应该是主机名 `192.168.1.124` 加端口 `8080` 两栏分开填。
5. **子文件夹填了没有。** 服务端是直接跑在根路径下的，这一项留空；只有走反向代理挂在 `/torrents` 这类子路径下才填，且要带前面的斜杠。填错就报 `Global value cannot be retrieved...` 这类取不到数据的错。
6. **服务端那台机器的 IP 变没变。** 家用路由器默认给设备动态分配地址，电脑重启后可能从 `192.168.1.124` 变成别的。建议在路由器里给这台机器做静态绑定（多数路由器的叫法是「IP 与 MAC 绑定」或「静态 DHCP」），一次解决。
7. **qBittorrent 是不是还在跑。** 电脑休眠、关机、退出程序，都会表现为连不上。手机端看不到服务端状态，只能从服务端那台机器确认。
8. **防火墙与安全软件。** 服务端那台机器的系统防火墙、第三方安全软件可能拦掉 8080 的入站连接。临时关掉防火墙试一次能立刻判断出来，确认是它之后再加放行规则，别长期关着。
9. **路由器/AP 的隔离设置。** 部分路由器的「访客网络」会开启「AP 隔离」，同一 Wi-Fi 下的设备之间互相看不见。把手机换到主网络试一次即可判断。
10. **服务端是不是开了 HTTPS 或换了端口。** 这两项改了而手机端没跟着改，表现就是连不上或报证书错误。对照服务端的当前配置，逐项同步过去。

## 三、401 那条：账号密码，以及别把 IP 试进小黑屋

`Unauthorized access. Check your account settings to avoid bans!` 这句里后半段是专门提醒：**连续登录失败到一定次数，服务端会临时拒绝来自这个 IP 的登录请求**（失败次数与封禁时长以服务端设置为准）。所以：

- 不要反复点重试。先停下，确认密码到底是什么，再试；
- 忘了密码，直接在服务端改一个新的：工具 → 选项 → Web UI → 认证，改完点应用，然后用新密码登录手机；
- 刚在服务端改过密码但手机还报 401，最常见的原因就是应用里没同步改（包括你把默认的 `admin` / `adminadmin` 换成了别的）；
- 少数情况下用户名也需要改：应用里默认填的是 `admin`，如果服务端把它改成了别的名字，这一栏同样要跟着改；
- **如果你从来没在服务端改过账号密码，先别怀疑自己填错** —— 较新版本的 qBittorrent 根本不接受默认的 `adminadmin`，它会在启动时生成一个随机临时密码，怎么找见 [服务端不认默认密码怎么办.md](服务端不认默认密码怎么办.md)。

## 四、密码明明是对的，还是报 401 / 403

这一节处理「凭据没错但登不进去」。下面两种原因都会让**浏览器也一起登不进去**，所以先用浏览器验证一次，能顺手排除掉应用本身的问题。

**原因一：Host 头与来源校验没过。**

服务端会核对请求里带的访问地址与来源，如果和你实际用的地址对不上，就直接拒绝。最容易触发的场景是走域名、反向代理，或从某个面板跳转过去 —— 表现为页面一打开就是一句 `Unauthorized`，或者应用里一直报认证失败。

处理顺序（从不动安全设置的那一头开始）：

1. 在服务端 Web UI 的设置里找到与「可以接受哪些域名 / 地址」有关的那一项（Host 校验的白名单），把你在用的域名或地址加进去；
2. 走反向代理时，让代理把原始 Host 头正确透传，不要把它改写成上游地址；
3. 上面两条都做不了、又确认只在完全自己可控的内网里用时，才考虑关掉「Host 头验证」与「跨站请求伪造（CSRF）保护」这两项防护。它们挡的正是别人从网页里偷偷指挥你下载器的那类攻击，关掉等于把这个口子一直留着，公网环境下不要关。

**原因二：来源 IP 被临时封禁。**

官方接口文档里写明，登录接口返回 403 的场景之一就是「该 IP 因失败次数过多被封」。遇到这种，等一段时间再试；同时别再连着点重试，那只会把封禁时间往后推。

## 五、HTTPS 与自签名证书

服务端开了 HTTPS、用的又是自己签的证书时，手机不认这张证书，就会报 `HTTPS certificate error!`。三条处理路径：

1. **先在手机浏览器里访问一次** `https://服务端IP:端口`，看浏览器是否也拦。浏览器都拦，说明确实是证书问题，不是应用的。
2. **在应用里指定证书。** `Settings` → 高级 → HTTPS 那一组，可以填自签名证书的 keystore 文件路径与 keystore 密码。这是给它一张「认可这张证书」的凭据，不是绕过验证。
3. **暂时只在局域网内用 HTTP。** 内网里不暴露到公网的前提下，把「启用 HTTPS」关掉、用 http 直连是最省事的做法。一旦要映射到公网，就应当把 HTTPS 配好，见 [在外网连接家里的服务器.md](在外网连接家里的服务器.md) 第三节。

顺带一提：应用在 HTTP 环境下正常工作，需要服务端允许明文 HTTP。如果服务端被设成只能 HTTPS 访问，而你在应用里关着 HTTPS 开关，也会连不上 —— 两边保持一致。

## 六、能连上但列表是空的

如果看到的是 `No torrents found`，说明认证已经通过、数据也拿到了，只是当前筛选下没有任务。按这个顺序确认：

1. 抽屉里切到 `All` 再看一次，可能当前停在 `Paused` 或某个分类下；
2. 搜索框里是不是还留着上一次的关键词，它会把列表筛空；
3. 服务端那台机器的 qBittorrent 里确实没有任务 —— 那就在这里加一个，见 [添加磁力链接与种子任务.md](添加磁力链接与种子任务.md)。

## 七、局域网通、出了门就不通

这一条不是故障，是设计如此：你在应用里填的是内网地址 `192.168.x.x`，离开这个网络自然找不到。两种正规做法（端口映射、组网）与各自需要改的设置，见 [在外网连接家里的服务器.md](在外网连接家里的服务器.md)。

## 八、逐条都试过还是不通

按下面这个顺序做一遍，能把范围压到最小：

1. 在服务端机器上确认 qBittorrent 在运行、Web UI 已勾选、端口号记下来；
2. 用服务端机器自己的浏览器访问 `http://localhost:8080`（换成记下的端口），能出登录页说明服务端没问题；
3. 用手机浏览器访问 `http://内网IP:端口`，能出登录页说明网络没问题；
4. 回到应用，按第 3 步验证过的 IP、端口、用户名、密码重新填一遍，注意主机名不带协议与端口、子文件夹留空；
5. 仍然报错时，把报错原文对照第一节的表格，回到对应那一节。

另外确认一下装的是不是本文档讲的这个应用：包名不同的同名应用，设置项与报错文案都可能不一样，见 [同名应用与官方渠道怎么认.md](同名应用与官方渠道怎么认.md)。
