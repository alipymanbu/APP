# qBittorrent Controller 连接服务器怎么设置

> 这个应用不会自己找服务器，所有连接信息都要你手填。设置分两半：先在跑 qBittorrent 的那台机器上把 Web UI 打开并记下地址、端口、账号，再到手机端把这几项填进去。本篇把两半的每一项都对着讲一遍。

## 一、它连的是什么

手机端发出去的每一个动作（看列表、暂停、加种、改限速）都落到服务端的 Web UI 接口上，走的是 Web API v2 这一套（qBittorrent 4.1 及以后提供）。所以：

- 服务端没开 Web UI，手机端填得再对也连不上；
- 服务端改了端口、开了 HTTPS、换了密码，手机端要同步改；
- 手机端不是「另一个下载器」，它看到的列表就是服务端那一份。

## 二、服务端这一半：把 Web UI 打开

在跑 qBittorrent 的那台机器上操作：

1. 打开 qBittorrent，进 工具 → 选项 → **Web UI**（部分版本写作「WEB 用户界面」）。
2. 勾选 **Web 用户界面（远程控制）**。不勾这一项，接口是关着的。
3. 记下 **端口**，默认是 `8080`。若这台机器上已有别的程序占了 8080，在这里改成别的并记住新端口。
4. 看 **认证** 一栏：默认用户名是 `admin`，默认密码是 `adminadmin`。**先把密码改掉再往下走** —— 用它对外意味着任何人猜到默认密码就能操纵你的下载。如果这一栏用默认密码根本登不进去（较新的 qBittorrent 已经不再接受默认密码，改为启动时随机生成一个临时密码），见 [服务端不认默认密码怎么办.md](服务端不认默认密码怎么办.md)。
5. 点「应用」保存。

顺便确认一项容易误会的设置：Web UI 里有个「跳过本机客户端的身份验证」（有的版本写作对 localhost 免验证）。它只对**运行 qBittorrent 的这台机器**有效 —— 手机上来的请求算另一台设备，仍然要账号密码。

**拿到内网地址**：在同一台机器上执行下面的命令，找 `IPv4`（Windows）或 `inet`（macOS / Linux）那一行的地址，形如 `192.168.1.124`。

Windows：

```powershell
ipconfig
```

macOS / Linux：

```bash
ifconfig
```

先在**手机浏览器**里验证一次：地址栏输入 `http://192.168.1.124:8080`（换成你查到的地址与端口）。能出现 qBittorrent 的登录页，说明服务端这一半已经合格，剩下的是手机端的事。打不开就先别折腾应用，按 [连接不上与报错排查.md](连接不上与报错排查.md) 第二节查。

## 三、手机这一半：账户这几项怎么填

路径：抽屉 → `Settings` → 账户这一组。逐项对照：

| 设置项 | 填什么 | 默认值 |
| --- | --- | --- |
| 选择 qBittorrent 服务器 | 免费版只有 `Server 1` 可用，`Server 2` / `Server 3` 需要付费的 PRO 版 | Server 1 |
| 连接主机（Connection Host） | 服务端的局域网 IP 或域名 | 空 |
| 用户名 | 服务端 Web UI 里设的用户名 | admin |
| 密码 | 服务端 Web UI 里设的密码 | adminadmin |
| 连接端口（在高级里） | 服务端 Web UI 的端口 | 8080 |
| 启用 HTTPS（在高级里） | 只在服务端已经用上 HTTPS 时才打开 | 关 |
| 子文件夹（在高级里） | 只在服务端挂在子路径下才填，例如 `/torrents`；不确定就留空 | 空 |
| 连接超时（秒） | 建立连接最多等多久 | 10 |
| 数据超时（秒） | 等数据最多等多久 | 20 |

三个最容易填错的地方：

1. **主机名不要带协议前缀。** 服务端是 `http://myserver.domain.com`，这里只填 `myserver.domain.com`；填 IP 同理，只填 `192.168.1.124`。
2. **不要把端口写进主机名。** 端口有单独一栏，`192.168.1.124:8080` 这种写法会连不上。
3. **端口留成默认的 8080 只在服务端也用 8080 时才对。** 服务端改过端口，这里必须跟着改。

改完密码那一项之后，回列表拉一次（点刷新，或抽屉里选 `All`），能出任务就说明通了。

## 四、家里家外两套地址：本地网络那一组

同一个人常常遇到这种麻烦：家里用内网地址 `192.168.x.x:8080` 最快，出门就得换成公网地址或域名。应用里给了一组专门解决它的设置（高级 → 本地网络）：

| 项 | 填什么 |
| --- | --- |
| Network SSID | 家里这个 Wi-Fi 的名称，注意大小写要一致 |
| Local Hostname or IP | 连上这个 Wi-Fi 时改用这个地址，一般填内网 IP |
| Local Port | 连上这个 Wi-Fi 时改用这个端口 |

填好之后，手机连到这个 Wi-Fi 时自动走本地那一组地址，离开后回到上面账户里填的那一组。只在家里用的话，这组留空就行。

## 五、自动刷新与完成提醒

同在 `Settings` 里，另有两组会影响手感和耗电：

**自动刷新（Auto Refresh）**

- 「自动刷新」默认是开的，间隔默认 `2 秒`；
- 可选间隔：1 秒、2 秒、5 秒、10 秒、30 秒、1 分钟、2 分钟、5 分钟、10 分钟、15 分钟；
- 间隔越短，界面越接近实时，但每一次都是在向服务端发请求，手机与电脑之间一直在通信。手机上看几眼就退出的，调到 30 秒以上更省电。

**通知（Notifications）**

- 「启用通知」默认开着，检查间隔默认 `5 分钟`；
- 可选间隔：2 分钟、5 分钟、15 分钟、30 分钟、1 小时、6 小时、12 小时、1 天；
- 它报的是「有任务下载完成」，靠的是后台定时去问服务端一次，不是实时推送，所以刚下完不会立刻响；
- 定时检查依赖「开机自启」权限，重启手机后没收到通知，先回 [下载与安装教程.md](下载与安装教程.md) 第六节看这一项。

## 六、服务端参数也能在手机上改

抽屉里的 `Options` 不是本应用的设置，而是**服务端的参数**，改完直接作用于那台机器上的 qBittorrent：连接数上限、单任务连接数、全局上传/下载限速、备用限速与其生效时段、任务排队（最大活动下载/上传/任务数）、分享率限制（做种到多少比率后暂停或删除）等。

三点注意：

- 每一项都在改真实的服务端配置，改之前想清楚影响范围，别在远程状态下把限速改到 1 KiB/s 然后自己都下不动；
- 「分享率限制」里的动作可选「暂停」或「删除」——选删除意味着达到比率后连同已下载的文件一起清掉；
- 「任务排队」这一组限制的是**同时活动的任务数**，调小之后多出来的任务会停在队列里等，手机列表上表现为一直「排队」。各状态在手机端怎么显示，见 [任务列表与详情怎么用.md](任务列表与详情怎么用.md) 第一节。

## 七、填完还是不通

先做三个判断，基本能把范围压到一半：

1. 用手机浏览器访问同一个地址（`http://服务端IP:端口`）。浏览器能出登录页、应用不行 → 问题在应用里填的这几项；浏览器也不行 → 问题在服务端或网络；
2. 看主机名那一栏有没有混进 `http://` 或端口号 —— 这两样混进去都会连不上；
3. 服务端改过端口、密码、HTTPS 或子路径之后，应用这边有没有同步改。

三条都对过还是不通，再按报错文案对号入座：那几条固定报错的原文、含义与查法全部列在 [连接不上与报错排查.md](连接不上与报错排查.md) 第一节。
