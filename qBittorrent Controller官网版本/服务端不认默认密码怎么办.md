# qBittorrent Controller 服务端不认默认密码怎么办

> 应用里密码那一栏默认写着 `adminadmin`，但服务端从 qBittorrent 4.6 系列起就不再接受这个默认值 —— 它会随机生成一个临时密码。这是「我什么都没改，怎么一直提示 401」最常见的原因。本篇讲这个临时密码在哪儿、怎么用它换成自己的密码，以及密码真忘了该怎么办。

## 一、先认出这个现象

两种表现，本质是同一件事：

1. 应用里用户名填 `admin`、密码填 `adminadmin`，刷新时弹 `Unauthorized access. Check your account settings to avoid bans!`；
2. 用手机浏览器打开 `http://服务端IP:8080`，**同样登不进去**。

第 2 条是关键判据：浏览器也登不进去，说明是服务端在拒绝，跟手机应用无关，别在应用里反复重试（连续失败次数多了会触发临时封禁，见 [连接不上与报错排查.md](连接不上与报错排查.md) 第三节）。

## 二、为什么默认密码不灵了

qBittorrent 项目的公开说明写得很直接：从 Web UI 的这次改动起，**没有自己设置过凭据的安装，默认凭据不再被接受**，程序会随机生成一个密码并打印出来，用于第一次登录。这条改动的版本号在不同来源里分别写作 4.6.0 与 4.6.1，按「4.6 系列起」理解即可。

也就是说：如果你的服务端是较新的版本，又从来没有在 Web UI 里改过账号密码，那么 `adminadmin` 已经不是有效密码了 —— 真正能用的是那个随机临时密码。

## 三、临时密码去哪找

临时密码只打印一次，位置取决于你怎么装的 qBittorrent：

| 服务端的装法 | 去哪里看 |
| --- | --- |
| Docker / NAS 容器 | 容器日志。命令行下用 `docker logs <容器名>`，NAS 上一般在套件或容器的日志界面里 |
| Linux 直接跑无界面版 | 启动时的控制台输出 |
| 桌面版（Windows / macOS / Linux 图形界面） | 启动后程序给出的提示，或程序内的执行日志 |

看到的是一串随机字符，不是 `adminadmin`。先拿它登录，登录成功之后立刻往下做第四步 —— 临时密码只该用一次。

## 四、登进去之后马上换成自己的

1. 用 `admin` + 临时密码登录服务端的 Web UI；
2. 进 工具 → 选项 → Web UI（部分版本写「WEB 用户界面」）→ 认证；
3. 把用户名和密码改成自己要用的，点「应用」；
4. 打开手机应用 → `Settings` → 账户，把用户名、密码同步改成新的；
5. 回列表刷新一次，能出任务就完成了。

第 4 步最容易漏：服务端改完、应用里没改，之后还是 401。

## 五、自己设的密码也忘了怎么办

服务端里没有「找回密码」这类入口，只能让它重新生成一个临时密码：

1. 先停掉 qBittorrent（容器就停容器）；
2. 找到它的配置文件（桌面版一般在用户配置目录下的 `qBittorrent` 文件夹里，文件名 `qBittorrent.conf`；Docker / NAS 版在你映射出去的配置目录里）；
3. 改之前先复制一份留底；
4. 在 `[Preferences]` 段里找到与 Web UI 密码有关的那一项（键名里带 `Password`，不同版本写法略有不同），把它整行删掉；
5. 保存后重新启动，程序会因为「没有设置过凭据」而重新生成一个临时密码，位置同第三节；
6. 拿到之后立刻按第四节设成自己的密码。

具体键名与步骤以 qBittorrent 官方文档的说明为准；这一步只用于自己的服务器，不要在共享或他人的机器上操作。

## 六、密码是对的、还是报 401 / 403

那就不是密码问题了，往下看两类原因：

- **Host 头与 CSRF 校验**：服务端会校验访问用的地址与请求来源，走域名、反向代理或面板跳转时容易被拒，表现为浏览器也登不进去。处理办法见 [连接不上与报错排查.md](连接不上与报错排查.md) 第四节；
- **临时封禁**：短时间内失败次数太多，来源 IP 会被临时拒绝登录，等一会儿再试，别连着点。

## 七、顺带提醒一句

如果你还没改过默认账号，改完密码后建议连用户名一起换掉（默认的 `admin` 是公开知识）。应用里账户那一组只有用户名与密码两栏，改完不需要重启应用，刷新一次列表即可生效。
