# qBittorrent Controller 在外网连接家里的服务器

> 出门在外想看一眼家里的下载队列，需要让手机能找到家里那台跑 qBittorrent 的机器。公开做法有三条：端口映射、组网、反向代理，安全代价差别很大。本篇讲三条路各自怎么搭、手机端要改哪几项、以及把 Web UI 暴露到公网前必须先做完的几件事。

## 一、三条路先选一条

| 做法 | 怎么工作 | 难度 | 暴露面 |
| --- | --- | --- | --- |
| 端口映射 | 在路由器上把外网某个端口转到家里的服务端 | 低 | 最大：Web UI 直接对公网开放 |
| 组网（虚拟内网） | 手机与服务端加入同一个虚拟内网，手机像在家里一样访问内网地址 | 中 | 最小：服务端不直接暴露 |
| 反向代理 | 用域名 + HTTPS 把 Web UI 包一层再对外 | 高 | 中，取决于证书与访问控制做得多严 |

判断标准很简单：**能用组网就别做端口映射**。家用宽带大多是动态公网 IP（甚至没有公网 IP），端口映射还要额外解决地址会变的问题；组网方案不依赖公网地址，也不需要在路由器上开洞。

## 二、端口映射这条路怎么走

1. **先给服务端机器固定内网地址。** 在路由器里做静态绑定（IP 与 MAC 绑定），别让它在重启后换 IP。
2. **在路由器里做端口映射（也叫端口转发 / NAT / 虚拟服务器）。** 规则形如：外部端口 `<你选的端口>` → 内部地址 `192.168.1.124`、内部端口 `8080`、协议 `TCP`。
3. **别指望 qBittorrent 里的 UPnP 选项帮上忙。** 那台机器的 qBittorrent 里确实有 UPnP / NAT-PMP 选项，但它是给 BT 的监听端口做映射用的，**不会**把 Web UI 的端口也映射出去。外网访问 Web UI 的规则仍然要在路由器里手动加。
4. **手机端改两处。** `Settings` → 账户里的「连接主机」改成家里的公网地址或域名；「高级 → 连接端口」改成第 2 步里选的**外部端口**（不是 8080，除非你把内外端口设成一样）。服务端开了 HTTPS 时同时打开「启用 HTTPS」。

家里的公网地址会变（多数家宽是动态分配），两个办法：路由器上开 DDNS 拿一个固定的域名（部分路由器与 qBittorrent 的 Web UI 设置里都提供了 DynDNS / No-IP 之类的入口），或者直接改用下面的组网方案。

## 三、暴露到公网前必须先做完的清单

Web UI 不是一个只读页面：拿到入口的人可以加任务、删任务、删文件、改限速。所以在这条路上，下面几件事是前提而不是可选项：

- **改掉默认账号密码。** 默认的 `admin` / `adminadmin` 是公开知识，留着等于没设密码。
- **能开 HTTPS 就开。** 明文 HTTP 在公网上传的账号密码是裸的。开了 HTTPS 之后，手机端也要把「启用 HTTPS」打开，二者必须一致。
- **外网不要沿用 8080。** 换一个不常见的外部端口，能挡掉大量无差别的扫描。
- **只放行需要的那一个端口**，不要顺手把整台机器暴露出去，也不要开 DMZ。
- **别用「跳过身份验证」这类选项。** 那些选项是为局域网内省事准备的，公网环境下一律关闭。
- **定期回服务端看一眼 Web UI 的日志**，确认没有陌生的登录尝试。
- **只在自家设备和自家账号上用。** 不要把 Web UI 的地址和账号给外部的人。

## 四、组网方案为什么更省心

思路是把手机和服务端放进同一个加密的虚拟内网，两者之间的访问和在家里局域网没区别：

1. 在服务端机器上装好组网客户端并加入你的虚拟网络，拿到它在这个虚拟网络里的地址；
2. 手机上装同一个组网客户端、加入同一个虚拟网络；
3. 应用里「连接主机」填第 1 步拿到的虚拟内网地址，端口仍填服务端的 Web UI 端口。

好处是服务端不用对公网开放任何端口、也不用管家里公网地址会不会变。代价是手机端要多常驻一个客户端，多一层进程，多耗一点电与流量。具体用哪个组网工具不在本文档范围内，选一个官方有明确文档、自己看得懂的即可。

## 五、反向代理这条路

已经有域名和一台常开的机器时，可以按 qBittorrent 官方的反向代理写法，把 Web UI 挂在某个子路径或子域名下，再由代理层统一做 HTTPS。

这条路有两个与本文档直接相关的注意点：

1. **挂在子路径下时，应用里的「子文件夹」必须填对应的路径**（例如代理把 Web UI 发布在 `/torrents` 下，这里就填 `/torrents`），否则会出现能连上、但取不到数据的情况；
2. **服务端会校验访问用的地址与来源**。换成域名访问之后，如果服务端认可的域名列表里没有这个域名，或者代理把原始 Host 头改写成了上游地址，就会一律被拒、页面打开只有一句 `Unauthorized`。把在用的域名加进服务端的允许列表、并让代理正确透传 Host 头，才算配完。

具体配置以 qBittorrent 官方文档的说明为准；被拒之后的排查顺序见 [连接不上与报错排查.md](连接不上与报错排查.md) 第一节与第四节。

## 六、改完之后怎么确认

1. 先把手机切到移动数据（关掉 Wi-Fi），确保是在「外网」状态下测试；
2. 打开应用刷新一次列表；
3. 通不了就按 [连接不上与报错排查.md](连接不上与报错排查.md) 的报错对照表定位：报地址不可达多半是外部端口或主机名填错，报 401 是账号密码，报证书错误是 HTTPS 那一层没对上。
