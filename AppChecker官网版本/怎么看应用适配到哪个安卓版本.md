AppChecker 的主列表会在每个应用旁边标出它的 Target API（目标 API 级别）。这个数字回答的是「这个应用的开发者是照着哪个 Android 版本做适配的」，不是「它只能装在哪台手机上」。本篇讲清这两者的差别，以及怎么把它换算成人能看懂的版本号。

## 一、Target API 到底在描述什么

一个 Android 应用在打包时会写进三个和系统版本有关的设定，官方文档里的名字分别是：

| 设定 | 含义 | 看它的用处 |
| --- | --- | --- |
| `minSdk` | 能运行这个应用的最低平台版本 | 判断你的手机能不能装 |
| `targetSdk` | 应用「设计为在该级别上运行」的目标版本 | 判断它有没有跟上新系统的行为变更 |
| `compileSdk` | 编译时用的系统 SDK | 多为开发者关心，普通用户不用管 |

AppChecker 列表上标的主要是 `targetSdk`。Android 在新版本里会改掉一些默认行为（权限、后台限制、存储访问范围等），并且对 `targetSdk` 还停留在旧版本的应用**继续沿用旧行为** —— 这既是为了不让老应用直接崩，也意味着它拿不到新系统带来的改进和更严的安全限制。所以你看到的目标版本越旧，基本可以理解成「这个应用越久没跟着系统升级更新过」。

## 二、API 级别换算成 Android 版本

AppChecker 在列表右侧用一个 Android 版本图标对应显示，数字与版本号的对照关系如下。Android 10 之后官方不再对外使用甜点命名，只按数字排。

| Android 版本 | API 级别 |
| --- | --- |
| 5.0 / 5.1 | 21 / 22 |
| 6.0 | 23 |
| 7.0 / 7.1 | 24 / 25 |
| 8.0 / 8.1 | 26 / 27 |
| 9 | 28 |
| 10 | 29 |
| 11 | 30 |
| 12 / 12L | 31 / 32 |
| 13 | 33 |
| 14 | 34 |
| 15 | 35 |
| 16 | 36 |

新版本发布后这张表会继续往后延伸，遇到表里没有的编号，按「编号越大越新」理解，具体对应关系以 Android 官方文档为准。

## 三、最常被看错的两点

1. **图标上的 Android 版本不是运行门槛。** 应用旁边显示 Android 17 之类的图标，意思是它按那个版本做的适配，不代表它只能在 Android 17 上跑、更不代表它要求你这么高的系统。能不能装看的是最低系统版本。
2. **目标版本低不等于应用一定有问题。** 有些工具类应用会**故意**把 `targetSdk` 留在较低级别，以便继续沿用旧的文件访问行为。看到低目标版本时，正确做法是结合应用的用途判断，而不是一律当成「该卸载了」。

反过来，如果你手机某次系统大版本升级后，有个以前正常的应用开始出问题，用这里的目标版本排序找一遍，往往能很快定位到那批没跟上适配的应用。部分应用在当前版本里能直接跳转到它的应用商店页面，用来看官方有没有发过更新；商店页面信息由商店决定是否更新，不一定和本机版本一一对应。

## 四、把它用起来的三个具体场景

- **清理久未更新的应用**：在列表里按目标版本从低到高看一遍，重点关注那些还在很旧版本上的应用，逐个确认是否还常用。
- **解释「为什么这个应用行为怪」**：老目标版本的应用在新系统上沿用旧规则，权限弹窗、后台存活、文件读写的表现都可能和同类的更新应用不一样。
- **给技术支持提供准确信息**：报障时把具体应用的目标版本、包名一起说明，比只描述「打不开」有用得多。

目标版本只是信息，不直接等于结论；真正决定你手机里应用装得下、跑得动的还有系统架构那一项，见 [怎么看应用是32位还是64位.md](怎么看应用是32位还是64位.md)。
