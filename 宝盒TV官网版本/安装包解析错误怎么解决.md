# 宝盒TV 安装包解析错误怎么解决

> 装的时候弹「解析包错误」「应用未安装」这类提示，原因就那么几类。本篇按报错分类给出对照，并说清怎么判断是文件问题还是设备问题。

安装失败的提示文字都很笼统，「解析包错误」这四个字底下藏着四五种完全不同的原因。本篇的办法是：**先按提示分类，再按分类走对应的那一条**，不要一上来就换包、换设备地乱试。

## 一、按提示文字先分类

| 你看到的提示 | 大概率是 | 看第几节 |
| --- | --- | --- |
| 解析包错误 / 无法解析软件包 | 文件不完整，或设备架构不支持 | 第二节、第三节 |
| 应用未安装 / 未安装该应用 | 签名冲突，或系统拦截 | 第四节、第五节 |
| 已被阻止安装 | 未知来源权限没开 | 第五节 |
| 安装失败，错误号 -24 或 -28 之类 | 直接查第六节的错误号表 | 第六节 |
| 装到一半提示空间不足 | 存储空间不够 | 第七节 |
| 装成功了，点开闪退 | 不是安装问题，见第八节 | 第八节 |

## 二、文件本身不完整

最常见的一种，也最好排。传输中断、U 盘拔早了、聊天软件转发截断，都会让文件少一截。

1. 重新从 [宝盒TV 安装文件资源（夸克网盘）](https://pan.quark.cn/s/ee8810ef35dc) 取一次包，**优先直接在电脑上下载**；
2. 下完在电脑上对一次 MD5，方法在 [下载与安装教程.md](下载与安装教程.md) 第三节，对的应该是 `d6712201b2be3b4601bf6129ba1a0fe6`；
3. 对得上再拷 U 盘。**不要用聊天软件发 APK 给自己** —— 部分工具会给文件改后缀或压掉一段，收到的包经常就是坏的。

## 三、CPU 架构不匹配

安卓应用的安装包可以只包含某一种处理器架构的原生库。装到架构不对的设备上，系统解不开包，报的也是「解析包错误」或者一个架构相关的错误号。

当前主流只有两类，判断方法很简单：

| 架构名 | 是哪些设备 | 兼容关系 |
| --- | --- | --- |
| `arm64-v8a` | 近几年出的大多数电视盒子、智能电视、手机 | 能跑 `armeabi-v7a` 的包 |
| `armeabi-v7a` | 较老的盒子与低配设备 | **跑不了**只带 `arm64-v8a` 的包 |

也就是说：**64 位设备装 32 位的包没问题，反过来通常装不上**。所以「同一份包，客厅的新盒子装上了，卧室那台老电视装不上」，多半是这台老设备是 32 位的。

查设备架构的两条路：

- 在设备上装一个设备信息类的工具应用（例如 CPU-Z、AIDA64、DevCheck 这一类），看「指令集 / ABI / 支持的 ABI」那一项，显示的串就是架构名；
- 设备的「设置 → 关于 → 硬件信息」里有的也能看到，写着 ARMv8 或 AArch64 就是 64 位，写着 ARMv7 就是 32 位。

**这一条排查完基本就能定性**：如果确认是老设备架构不匹配，换个包也解决不了，只能换设备或找该设备能用的版本。

## 四、签名冲突：装过别家的同一应用

提示「应用未安装」，而且这台设备上**以前装过名字一样的应用**，多半是签名冲突：同一个包名、但两次拿到的包签名密钥不同，系统不允许覆盖。

处理办法只有一个方向：**先把旧的那个卸掉，再装新的**。

- 卸载会连它的数据一起清掉（配置、收藏、观看记录都在里面）。**卸之前先把配置地址拍照记下来**，否则装完新的还得重新敲一遍。
- 卸完如果应用列表里图标还在，重启一次设备再看。

## 五、被系统拦下

电视和盒子对非商店来源的应用有额外策略，各家程度不一：

- **没开未知来源**：按 [下载与安装教程.md](下载与安装教程.md) 第五节放行，注意要放行**你实际用来安装的那个应用**（文件管理器或浏览器）。
- **厂商内置的白名单机制**：部分品牌的系统会拦下不在它名单里的第三方包，且提示含糊。这种情况的正确做法是**换安装方式**：优先改用 U 盘装（走系统自带的文件管理器），而不是去关掉设备的安全功能 —— 关掉安全功能风险大、收益小，不值得。
- **下载来源的应用本身没有安装权限**：从浏览器直接装失败时，把包拷到文件管理器里再点开装，往往就过了。

## 六、常见错误号对照

如果提示里带了错误号，直接查这张表。带横杠的负数（`-11`、`-24`）和 `INSTALL_FAILED_` 开头的写法是同一种东西的不同呈现。

| 错误号 | 含义 | 怎么处理 |
| --- | --- | --- |
| `-11` / `INSTALL_FAILED_INVALID_APK` | 包损坏或签名无效 | 回第二节重新下载并校验 |
| `-24` / `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | 已有同包名但签名不同的应用 | 回第四节，卸载旧版再装 |
| `-28` / `INSTALL_FAILED_NO_MATCHING_ABIS` | CPU 架构不匹配 | 回第三节确认设备架构 |
| `-29` | 包的签名方案不被现有系统支持 | 多为下载源重新打过包，换正规来源取包 |
| `-110` / 空间不足 | 存储空间不够 | 回第七节 |
| `-113` / 安装器进程崩溃 | 系统安装器出问题了 | 先重启设备再装；重启无效就换 U 盘方式试 |

## 七、空间不够

- 需要的是**空闲空间**，不是总空间。装一份 54.35M 的包，建议留出不小于它两倍的余量，因为安装过程要额外解压。
- 电视和盒子的机身存储通常很小，装之前顺手看一眼剩余空间；不够就先删掉不用的应用或清空它们的缓存。
- 如果 U 盘一直被识别成安装位置，注意别把包装到 U 盘上 —— 装完把 U 盘拔了应用就没了。

## 八、装上了但点开就退

这已经不是安装环节的问题了，多半是设备性能或系统版本跟不上。**最快的判断方法是在另一台设备上装同一份包**：

- 别的设备能正常打开 → 是这台设备的问题（内存小、系统版本低、机器过热降频）；
- 别的设备也一样 → 才是这个包本身在这套系统上跑不起来。

这种情况不用在安装上继续折腾，换到排查播放与设备性能那条线上，按 [加载不出内容与播放卡顿怎么排查.md](加载不出内容与播放卡顿怎么排查.md) 第三节那张顺序表往设备这侧走。
